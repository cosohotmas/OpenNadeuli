# 프런트 API 기본 경로

## Why

휠체어 이용자가 배포된 오픈나들이에서 코스를 요청하면 브라우저가 사용자 기기의 8899 포트로 접속한다. 프런트가 전송한 요청이 실제 백엔드에 도달하고 코스 응답을 받는지 확인한다.

## Goal

- 로컬 Vite 개발·프리뷰와 Vercel에서 각각 코스 요청 1건 이상이 HTTP 200과 `answer`를 반환한다.
- 프런트 배포 번들에 `127.0.0.1:8899`가 0건 포함된다.
- 범위 제외는 설정 API 인증, CORS 정책 변경, Vercel 라우팅 및 배포 설정 변경이다.

## What

- 정상 경로는 프런트가 현재 origin에 `POST /api/course`를 보내고 응답을 렌더링하는 것이다.
- 백엔드가 오류 상태를 반환하면 기존 프런트 오류 처리 흐름을 사용한다.

## How

- 프런트 API 기본 경로를 `/api`로 설정한다. 요청 본문과 응답 스키마는 유지한다.
- Vite 개발 및 프리뷰에서 `/api/`로 시작하는 요청을 `http://127.0.0.1:8899`로 전달한다. 요청 경로를 바꾸지 않는다.
- Vercel에서는 동일 origin의 API 라우팅을 사용한다.

## AC

- Given 백엔드와 Vite 개발 또는 프리뷰 서버가 실행 중이다. When 브라우저가 코스 요청을 보낸다. Then Vite가 `POST /api/course`를 백엔드로 전달하고 프런트가 200 응답의 코스를 표시한다.
- Given 프로덕션 빌드를 실행한다. When 생성된 JS에서 API 기본 경로를 확인한다. Then `/api`를 사용하고 `127.0.0.1:8899`를 포함하지 않는다.
- Given Vercel 배포가 완료됐다. When 배포 URL에서 코스를 요청한다. Then 브라우저가 같은 origin의 `/api/course`에서 200 응답을 받고 코스를 표시한다.
